Featured project

AI Document Analysis Platform

A microservice platform for uploading PDFs, indexing them for retrieval-augmented generation (RAG) and chatting with them through an LLM (Gemini). The problem it addresses: letting a signed-in user ask questions and get answers drawn from their own documents.

Services

  • Gateway :8000Public entry point, Redis rate limiting, proxies requests
  • Auth :8001Register, login, refresh; issues JWTs
  • Document :8002PDF upload, text extraction, chunking, queues the embedding job
  • Chat :8003RAG query: retrieval, Gemini call, Redis cache and sessions
  • AI worker :8004Celery worker and beat, embeddings, FAISS, internal search API

Sign in

  1. Client registers or logs in through the gateway.
  2. Auth service issues a JWT.
  3. Other services verify it locally with the shared secret, with no call back to auth.

Upload a PDF

  1. Gateway rate-limits the request and proxies it.
  2. Document service extracts text, chunks it and stores a record in PostgreSQL.
  3. It queues a Celery task through RabbitMQ.
  4. The AI worker embeds the chunks and indexes them in FAISS.

Ask a question

  1. Chat service checks Redis for a cached answer and the session.
  2. It calls the AI worker’s internal search to retrieve relevant chunks.
  3. It sends the chunks and question to Gemini and returns the answer.

Engineering decisions

  • Redis only for caching, sessions and rate limiting. RabbitMQ only as the Celery broker.
  • Every service-to-service HTTP call goes through one shared client with retries and a fixed timeout.
  • No service imports another’s code; they talk over HTTP or Celery task names.
  • Alembic migrations, and a route → service → repository layout that lets tests swap in fake repositories.

Quality

  • Unit and API tests per service, including property-based tests for the PDF chunker.
  • Vector search is scoped to the owning user.
  • Configuration such as the JWT secret and Gemini API key comes from environment variables (.env).

Scope. Docker Compose runs PostgreSQL, Redis and RabbitMQ; the services run locally as Python processes. The FAISS index is local, and there is no hosted demo. The README explains how to run everything.
